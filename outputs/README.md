# Outputs and figure provenance

## What is committed here

- `outputs/tables/` and `outputs/tables_10m/` - the **aggregate** result tables reproduced in the thesis (class-level and summary statistics only). Every table carrying coordinates, per-unit identifiers, or per-unit/per-pixel rows was screened out; the screening record is `docs/table_screening.json`.
- `outputs/provenance/` - run manifests recording grid definition, cell counts, the **0.502** operating threshold, layer checksums and QA results.

Raster surfaces, GeoPackages and per-unit tables are **not** committed: they are large and they are derived from the restricted fire-reference inventory and land-cover product.

Three further directories hold records that are not prefix-numbered tables:

- `outputs/figures/*.md` and `diagnostics/nb13_landcover_timing/figures/*.md` - the
  caption-and-method notes written beside each figure. The figure images themselves are
  not committed; these notes record what each one plots and from which inputs.
- `outputs/final_polygon_maps/`, `outputs/polygon_10m_candidate/maps/` - figure
  provenance records and the geometry validation report.
- `outputs/final_polygon_thesis/` - the class-level summary tables and the final output
  registry. The two per-unit tables in that directory in the original project
  (`model_units_final.csv`, `reference_units_final.csv`) are **not** committed: they
  carry `east`, `north` and `unit_id` columns.

The 30 m indicator rasters those analyses read are produced by the
`pipeline/07a` to `07c` chain; the 10 m surfaces are produced by
`inference_10m/run_inference_10m.py` and `mosaic_10m.py`. Neither set of rasters is
committed.

## Figure provenance

Established by hashing the images embedded in the final thesis against every image file
in the project **and** every image stored in a notebook output cell. Figure numbers
below are the **final thesis numbers**. Several script names still carry
pre-renumbering numbers; that is deliberate, because provenance JSONs and saved output
files hash those names.

Two properties are recorded and must not be conflated:

- **Role** - the figure's standing in the thesis: main-text result, supporting,
  appendix diagnostic, or conceptual diagram.
- **Implementation** - the resolution of the code that rendered it: **10 m** (the final
  regional pipeline, which produced the reported region-wide results) or **30 m** (the
  earlier supplementary implementation).

A figure can be a main-text result whose image was rendered by the 30 m implementation.

### Unresolved: Figures 2 and 4

The land-cover map for 2025 (1010x986) and the fire-reference polygon map (1232x964)
match nothing in the project, by hash or by aspect ratio. They were most likely rendered
in an Earth Engine Code Editor or Colab session that was not retained. **No replacement
script is provided**, because a new script would be a reconstruction, not the provenance
of the published image.

### Figures 1 and 6 are a different case

Both were drawn by deterministic specification scripts with **no data access at all** -
zero array reads, zero table writes. They are diagrams of the thesis text, so the code
that draws them is document-formatting code and is deliberately not published. This is
not a gap in scientific provenance: every number in Figure 6 is transcribed from Table 3,
which is published.

### The legacy "Ground-truth fire polygons" label

`supplementary_30m/compose_fig_4_2_and_4_3.ipynb` writes the panel heading
"Ground-truth fire polygons" into Appendix Figure A.2. The string is retained
deliberately and the thesis caption discloses it: throughout the thesis those polygons
are treated as a documented fire-reference inventory, not as validated ground truth.

### Provenance strings inside generated files

The `nb08_*` and `nb09_*` `.md` tables, and the Experiment 5b records, carry
"generated by ..." lines quoting notebook paths **as they were when those files were
produced** (`notebooks/08_...`, `notebooks/09_...`). Those strings are left exactly as
written so that re-running the code reproduces the committed artefacts byte for byte.
Use the table at the top of this file for current locations.

## Reproducing the figures

```bash
# public, runs immediately
python figures/22_study_area_environment.py

# final 10 m figures - requires restricted inputs in data/restricted/
bash inference_10m/run_pipeline.sh
```
